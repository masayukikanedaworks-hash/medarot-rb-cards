# 通り芯照合ツール 開発メモ

基準図面と比較図面（ベクター PDF）から通り芯と芯々寸法を抽出して照合する、
単一 HTML で完結するブラウザアプリ。概要と使い方は [README.md](./README.md)。

## コマンド

```bash
npm test          # 回帰テスト（Node 18+ / 外部依存なし）
npm run build     # dist/zumen-check.html を再生成
```

コミット前に必ず両方を実行し、`dist/zumen-check.html` も一緒にコミットする
（利用者はビルドせずに dist を直接開くため）。

## 構成

```

src/js/00_ns.js     名前空間 ZC

src/js/10_filters.js  FlateDecode（DecompressionStream使用）・予測子・各種フィルタ
src/js/11_lexer.js  PDF構文の字句解析とオブジェクト組み立て
src/js/12_pdf.js    xref（表/ストリーム）・ObjStm・ページ列挙・ストリーム復号
src/js/13_fonts.js  ToUnicode CMap / 単純エンコーディング / 字幅
src/js/14_content.js  コンテントストリーム解釈 → 線分・テキスト抽出

src/js/24_compare.js  2図面の照合（辺ごとに通り芯・芯々寸法・全体寸法）
```

## コーディング規約

- **import/export 禁止**。ファイルは `_order.json` の順に連結されるため、
  各ファイルは `(function (ZC) { ... })(globalThis.ZC = globalThis.ZC || {})`
  で名前空間 `ZC` にぶら下げる。
- 実行時依存・CDN・fetch は追加しない（オフライン動作と「外部送信しない」が要件）。
- ビルド時依存も追加しない（Node 標準モジュールのみ）。
- DOM 操作は `30_ui.js` / `31_app.js` に閉じ込める。それ以外のモジュールは
  Node のテストから直接呼べる純粋ロジックに保つ。
- 単位はコメントが無い限り pt（1/72 インチ）。**mm 値は図面の記載寸法だけ**で、
  pt から mm への換算は行わない（縮尺を使わない仕様）。

## 座標系

- 抽出結果はすべて「表示向き」のデバイス座標（y 上向き・pt）。
  ページの `/MediaBox`(`/CropBox`) 原点補正と `/Rotate`(90/180/270) の回転は
  `14_content.js` の run() が吸収する。以降の層は回転を意識しない。
- Canvas 描画時のみ y を反転する（`30_ui.js`）。

## 通り芯検出の考え方（20_axis.js）

1. 軸平行（縦/横）の線分を位置でクラスタリング（`CLUSTER_TOL` = 0.35pt）。
2. 同一クラスタ内の区間を `GAP_TOL`(14pt) 以内の切れ目で連結し、最長チェーンを採用。
   一点鎖線は「d パターン付きの1本線」でも「短い線分の連なり」でも出力されるため、
   後者は本数とカバー率（`CHAIN_*`）で鎖線相当と判定する。
3. 長さが `max(MIN_LEN_ABS, MIN_LEN_RATIO × 内容範囲)` 未満は捨てる。
4. 符号は **円（バブル）で囲まれた** 「縦芯 = X○○ / 横芯 = Y○○」のみ
   （`util.axisLabelOf`、X2.5 のような小数点付きも可）。`14_content.js` が閉じた
   円形サブパスを `circles` として集め、その中にある符号テキストだけを候補にする。
   方向が一致し、芯の延長線上（`BUBBLE_REACH`）にあるものを横ずれ優先で割り当てる。
5. **拾い出し対象は円囲み符号が付いた芯のみ**（図枠疑いは除く）。符号なしの芯は
   一覧にも出さない。誤検出はビュワーのクリックか一覧のチェックで除外できる。
6. 符号は芯の上下（左右）両端に 2 回書かれる。各バブルは `ax.bubbles` に
   `{label, x, y, side}` として記録し、**辺（top/bottom/left/right）** を決める。
   同一の「符号+辺」は 1 本の芯にのみ割り当てる。

## 辺別の拾い出し（23_sides.js）

上辺・右辺・下辺・左辺それぞれについて:

- その辺にバブルがある芯を位置順に並べる。
- 隣り合う芯の組ごとに、**その 2 本の芯の外側の端から `SIDE_BAND`(72pt) 以内**に
  ある寸法段だけを使って記載寸法を読む。芯の長さが場所で変わる図面（平面が
  2 区画に分かれている等）に対応するため、辺の判定は 2 本の芯自身の範囲で行う
  （図面全体の中心では判定しない）。これで室内寸法など内部の段を拾わない。
- 表記は `X1~X2：5917（2730.5+3186.5）`（`formatSpan` / `formatText`）。

検出のしきい値は `ZC.axis.PARAMS`、寸法読み取りは `ZC.dims.PARAMS` に集約。
実図面で調整するときはここを触り、必ず `test/make_pdf.js` に再現ケースを
足してから変える。

## 記載寸法の読み取り（22_dims.js）— このツールの寸法の一次情報

寸法は**作図距離の測定値ではなく、図面に記載された数字**を読む。構造は
「黒いドット（塗り潰しの小円・太線の点）間の直線の上にある数字」:

1. `14_content.js` が塗り潰しの極小図形（`DOT_MAX`=3.2pt 以下）と
   太線の極小ストロークを `dots` として収集する。
2. ドットを寸法線の位置（横段なら y、縦列なら x）で「段」にグループ化し、
   隣接ドット対のあいだに直線が実在するか確認したうえで、線の上
   （横段=上側 / 縦列=左側優先・90度回転文字）にある数値を対応付ける。
   "3" "000" のように分かれたランは `mergeTexts` で結合してから読む。
3. 芯々の記載寸法は `spanValue()`: 分割記載はチェーンの合計。複数の寸法段が
   該当するときは分割数の少ない段（通り寸法の段）を優先し、段どうしで値が
   食い違えば `conflict` を立てる（照合結果の備考に出る）。
4. 数値は小数点付きも可（`parseDimNumber`、全角・カンマ許容、2〜5桁 + 小数）。

## 縮尺

**使わない。** 寸法はすべて図面の記載値。作図距離は測定機能（pt表示）と
段内整合チェック（比率のみ）に使うだけで、mm 換算はしない。

## 照合（24_compare.js）

- **辺ごとに**照合する。通り芯の対応は符号（X○○/Y○○）の一致のみで判定し、
  欠落・余分・並び順の違いを NG にする。
- 芯々寸法・全体寸法は**記載寸法どうし**で比較（分割は合計し、内訳を備考に表示）。
  どちらかで記載寸法が読めない区間は NG ではなく **要確認(WARN)**。
- 判定は `|差| ≤ 許容差(mm)`。既定 1mm。

## ビュワー（30_ui.js の Panel）

- ページ座標(pt, y上向き) ⇔ 画面座標の変換は `toScreen()/toPage()` に集約。
  ビュー状態は `panel.view = {scale, ox, oy, fitScale}`（null なら次描画でフィット）。
- 描画は `requestRender()`（rAFで間引き）経由で呼ぶ。直接 `renderCanvas()` を
  呼ぶのは初期化時のみ。可視範囲外の線分はカリングして描かない。
- 操作: ホイール=ズーム / ドラッグ=パン / ダブルクリック=フィット /
  芯クリック=拾い出しON/OFF（`_hitAxis` は画面座標で6px以内） /
  測定モード=2点間距離（縮尺を使わないので pt 表示。`_snap` が芯位置と
  線分端点へスナップ、Escで解除）。
- 寸法オーバーレイ（`_drawDims`）は辺ごとに、その辺の記載寸法を外側へ描く。
  区間が画面上34px未満なら数値を省略。分割内訳がある区間は値に `*` を付ける。
- 照合結果の行は `row.refs = {b:[芯...], c:[芯...]}`（列挙不可プロパティ）を持ち、
  行ホバーで両パネルの `setHighlight()` を呼んで該当箇所を強調する。
  refs は enumerable:false なので JSON/CSV には出ない（テストで担保）。

## PDF パーサの対応範囲と既知の制限

対応: クラシック xref・xref ストリーム（PNG 予測子）・ObjStm・ハイブリッド参照・
FlateDecode/ASCIIHex/ASCII85/RunLength・Form XObject（再帰8段まで）・
インライン画像の読み飛ばし・Type1/TrueType（WinAnsi/Differences）・
Type0 Identity-H + ToUnicode・TJ/Tj/'/" と全テキスト行列・xref 破損時の全走査復旧。

非対応（明示エラーまたは無視）:

- 暗号化 PDF → 読み込み時に日本語エラー
- LZW / 画像系フィルタのコンテント → そのストリームだけスキップ
- Type3 フォントの FontMatrix、縦書き（Identity-V）
- OCG（レイヤ）の表示状態 → 非表示レイヤも抽出対象になる
- 塗り（f）のみの図形 → 線分にしない（ハッチング対策）。輪郭が塗りだけの
  通り芯は検出できない
- 符号が円で囲まれていない図面（四角囲み・囲みなし）→ 拾わない仕様
  （`14_content.js` の `scanCircles` を四角対応に広げる必要がある）

## 落とし穴メモ

- **CAD は寸法数字1行分を 1 つの TJ にまとめて出力することがある**（実図面で確認）。
  `14_content.js` は TJ 内のカーニングが `TJ_SPLIT`(0.4em) を超えたら別ランに分割する。
  これを外すと数字が連結されて全滅する。逆に `22_dims.js` の `MERGE_GAP` は
  TJ 分割を再結合しない値（0.25em）にしてある。両者の関係を崩さないこと。
- 狭い区間の寸法数字は 90 度回転（縦書き）で書かれる。寸法の数字対応付けは
  両方の向きを受け付け、回転文字は「線に近い側の端」で浮きを測る。
- `DecompressionStream("deflate")` は末尾ゴミで例外を投げる実装がある。
  `10_filters.js` の inflate は 3 段フォールバックを持つ。順序を変えないこと。
- CAD からの出力は一点鎖線を数百の微小線分に分解することがある。
  `MIN_PIECE_LEN` を上げすぎると鎖線の破片を拾えなくなる。
- 通り芯符号は全角（Ｘ１）で入っていることがある。比較は必ず
  `ZC.util.normalizeLabel` を通す。
- 芯の絶対位置は図面ごとに原点が違うため意味を持たない。照合は必ず
  「差分（芯々・全体）」で行う。オフセット合わせは matchAxes 内のみ。
- テストは連結後のソースを `(0, eval)` で読み込む。つまり **テストが通る =
  連結順が正しい** ことの検証を兼ねる。`_order.json` を変えたら必ず npm test。

## 実図面で確認済みの挙動（1F平面図・A1・線分9万本超）

- 円囲み符号 17 本（X1〜X11 / Y1〜Y5・Y4.7）を検出し、4 辺すべてで寸法を読む。
- 上辺と下辺、右辺と左辺で同じ値が出ることが精度の目安になる
  （例: X1~X2 は上下とも 5915、Y1~Y2 は左右とも 5915）。
- 芯の長さが場所で変わるページでは、区間ごとの局所判定が効いて別区画の
  寸法段も正しく読める。

## テスト方針

実 PDF はリポジトリに置かない（図面は顧客資産のため）。代わりに
`test/make_pdf.js` が通り芯・壁二重線・寸法線・図枠・ノイズ・バブル円を含む
合成図面を 2 系統の PDF 構造（クラシック xref / xref ストリーム+ObjStm+Type0）で
生成し、検出→記載寸法の読み取り→辺別の拾い出し→照合の全経路を回す。
合成図面は 4 辺すべてにバブル付き符号と寸法段（下辺は分割段付き）を持つ。
不具合を直すときは、まず make_pdf.js のパラメータで再現ケースを作ってから直すこと。
